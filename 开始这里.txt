============================================================
  护士电子化注册信息系统 - 使用说明
============================================================

【第一步】启动服务

    双击本目录下的  一键启动.bat

    会弹出一个黑色窗口，窗口里出现下面这段就说明成功了：

        服务启动中，请勿关闭本窗口
          后台管理    http://localhost:3000/admin
          前台登录页  http://localhost:3000/login.html

    >>> 这个窗口不要关！关了服务就停了。 <<<


【第二步】打开网站

    在浏览器地址栏输入：

        后台管理    http://localhost:3000/admin
        前台登录页  http://localhost:3000/login.html

    如果 localhost 打不开，换成：
        http://127.0.0.1:3000/admin

    !! 重点：不要直接双击 public\admin\index.html 打开 !!

       直接双击 HTML 文件是以 file:// 方式打开的，浏览器不允许
       网页访问后台接口，页面会一直停在「加载中…」，看起来像卡死。
       一定要走上面的  http://localhost:3000/admin  地址。

       （新版已加检测：万一你这样打开了，页面会直接弹提示告诉你
         正确做法，不会再让你对着转圈的表格干等。）


【登录账号】

    后台管理员（新增的增删改查界面）
        账号：admin
        密码：见项目目录下的 .env 文件里的 ADMIN_PASSWORD
              （首次启动时也会打印在启动日志里）

    前台用户（原项目自带的页面）
        账号：见后台「账号管理」页里列出的账号
        密码：新增账号时自己设置的

    说明：本项目配套的 GitHub 仓库是**公开仓库**，所以这份说明里
          不写任何真实账号口令与身份证号，请以上面写的位置为准。


【后台新增的实用功能】

  1. 新增账号表单默认值（少点几次）
     执业注册状态 = 在册（自动填好）
     国籍        = 中国（自动填好）
     民族        = 汉族（自动填好，可以改）
     健康状况    = 健康状况良好（自动填好）

  2. 头像可以选本地图片
     点「选择本地图片」→ 从电脑里挑一张图 →
     系统自动压缩后上传，头像框里会出现缩略图。
     上传后会自动填好「头像」地址，不用手写。
     想换回文字地址：直接在「头像」输入框里改；
     想清空：点「清除头像」。

  3. 「随机生成」按钮（表单最下面）
     点一下，自动填好一整份测试样本
     （姓名、身份证号、证书编号、机构、科室、职称…全都有，
       身份证号的校验位是按国家标准算出来的，格式合法）。
     密码也会自动生成，直接点「保存」就能存进系统。
     适合反复造数据做测试。

  4. 「预览信息页」按钮（账号列表每行的第一个图标）
     新开一个窗口，直接看到这个账号在前台长什么样。
     不用退出后台、也不用去前台登录，看一眼就知道效果。
     预览窗口顶部会有一条淡蓝色提示，说明这是预览。

  5. 「推送仓库」列（账号列表每行都有，按单个账号推送）
     每个账号后面有两个小按钮：

        ☁ 推送上云   生成这个账号的**加密信息页**并提交到仓库
                     （没推过就是新增，推过就更新为最新内容）
        ↩ 撤回       把这个账号的信息页从仓库里撤下来，
                     本地数据不受影响，随时可以再推上去

     这一列最前面还有个状态标记，一眼看出每个账号的情况：
        已推送   仓库里的内容与你本地一致
        有改动   你改过这个账号但还没推上去
        未推送   这个账号还没进仓库
        未知     没配令牌或断网，暂时查不到

     推送是**按单个账号**进行的：新增一个账号就点它那一行的「推送」，
     不会影响其他账号，也不会把别的账号未推送的改动带上去。

     表格最上方那条浅蓝/浅黄的状态条会汇总：
        共几个账号、已推送几个、有几个还没推。


【给护士看的页面：一账号一链接 + 页面密码】

  站点地址（公开，谁都能打开，但看不到任何内容）：
      https://ffamx.github.io/nurse-registry/

  每个账号一条独立链接，长这样：
      https://ffamx.github.io/nurse-registry/accounts/03c57a5c81.html
                                                  ^^^^^^^^^^ 10 位随机短码

  打开链接会要求输入**这个账号专属的页面密码**，
  密码正确才会在浏览器里解密出信息；密码不对就只是一堆乱码。

  页面密码在哪看：
      后台 → 账号列表 → 「推送仓库」列里推送成功后，
      会显示该账号的链接和密码，复制发给本人即可。
      也可以在账号的「页面密码」那里重新生成或手动指定。

  ★ 为什么这样设计、为什么仓库公开也没事：
      GitHub Pages 只能放静态文件，**没有服务端**，
      做不了真正的「登录后才显示内容」。
      所以这里不是靠登录拦人，而是把内容**加密**后再发布：
        · 仓库里 docs/accounts/*.html 全都是密文，没密码解不开；
        · 头像照片内嵌进密文，仓库里看不到任何照片文件；
        · 文件名是随机短码，不含身份证号；
        · 页面里显示的身份证号是打码的（保留前 4 位与后 4 位）。
      也就是说：**仓库公开 = 别人能看到"有这些页面"，但看不到任何内容。**

  日常操作：
      新增/修改某个账号 → 点它那一行的「推送」→ 等 1~2 分钟
      （GitHub 要重新构建站点）→ 把链接和密码发给本人。
      想下架某个账号 → 点它那一行的「撤回」，本地数据不动。


【关于仓库与令牌 · 首次配置记录】

  仓库地址（公开）：
      https://github.com/FFAMX/nurse-registry

  说明：
      · 仓库里只有程序源码和**加密后**的页面，不含任何明文资料；
        账号数据始终留在本机的 data\db.json 里，不会上传。
      · 令牌只保存在本机的 .env 里，不会上传到任何地方。
      · 令牌过期了就重新生成一个，替换 .env 里的 GITHUB_TOKEN。
      · 邮箱收不到 GitHub 通知是正常的，本仓库未开启 Issues/Wiki。

  第 1 步  建仓库
      用你的 GitHub 账号（FFAMX）建一个仓库，名字 nurse-registry。
      本项目用**公开仓库**，因为免费账号的 GitHub Pages 只在公开仓库可用。

  第 2 步  生成访问令牌
      GitHub 右上角头像 → Settings → Developer settings
        → Personal access tokens → Fine-grained tokens → Generate new token

      勾选这些权限：
          Repository permissions → Contents: Read and write     （必须）
          Repository permissions → Metadata: Read-only          （会自动勾上）
          Account permissions    → Administration: Read and write
      想让程序用接口自动开关 GitHub Pages 的话，再加一项：
          Repository permissions → Pages: Read and write

      Repository access 选择：All repositories（或指定上面那个仓库）

  第 3 步  把令牌填进配置文件
      用记事本打开本目录下的  .env  文件，找到这一行：

          GITHUB_TOKEN=

      等号后面粘贴你的令牌，保存。

  第 4 步  重启服务
      双击  停止服务.bat  ，再双击  一键启动.bat

      回到后台页面，账号列表下方会出现一条浅蓝色状态条，
      写着「仓库 FFAMX/nurse-registry……」，说明配置成功。

  第 5 步  开启 GitHub Pages（只需要做一次）
      打开  https://github.com/FFAMX/nurse-registry/settings/pages
        · Source 选 “Deploy from a branch”
        · Branch 选 “main”，目录选 “/docs”，点 Save
      等 1~2 分钟，上面的站点地址就能打开了。
      （如果第 2 步勾了 Pages: Read and write，这一步可省。）



【停止服务】

    双击  停止服务.bat


------------------------------------------------------------
  遇到问题怎么办
------------------------------------------------------------

问题：双击后一闪就退，什么都看不到
    改用  start.bat  （它会一步一步显示过程，不会闪退）

问题：浏览器显示"无法访问此网站"
    1. 先确认启动的黑色窗口还开着没有
    2. 试 http://127.0.0.1:3000/admin
    3. 双击  诊断.bat  ，把窗口内容截图发出来

问题：提示端口 3000 被占用
    先双击  停止服务.bat  ，再重新启动

问题：想以后台方式运行（不显示黑窗口）
    双击  运行服务.vbs  （启动成功/失败都会弹窗告诉你）

问题：后台页面打开后一直显示「加载中…」像卡死
    1. 多半是直接双击了 HTML 文件（file:// 打开），
       请改成访问 http://localhost:3000/admin
    2. 也可能是服务没启动，先双击  一键启动.bat

问题：某一行的「推送」按钮是灰的，点不动
    说明还没配置令牌，或者 .env 里的 GITHUB_TOKEN 是空的。
    按上面【关于仓库与令牌 · 首次配置记录】做一遍即可。
    按钮上鼠标悬停会直接说明原因。

问题：「撤回」按钮是灰的，点不动
    说明这个账号本来就没推到仓库上，没什么可撤的。
    悬停会有提示。

问题：状态标记一直显示「未知」
    说明连不上 GitHub 查不到仓库状态。检查网络能否打开
    https://api.github.com ，或令牌是否还有效。

问题：点「推送」提示「令牌无效或已过期」
    令牌填错、或者生成后失效了。重新生成一个，
    更新 .env 里的 GITHUB_TOKEN，然后重启服务。

问题：点「推送」提示「找不到该仓库或令牌无权访问」
    1. 确认 GitHub 上已经建好仓库 nurse-registry
    2. 确认令牌的 Repository access 里包含了这个仓库

问题：推送成功，但打开链接一直 404
    说明 GitHub Pages 还没开启，或者刚开还在构建。
    1. 打开 https://github.com/FFAMX/nurse-registry/settings/pages
       确认 Source 是 “Deploy from a branch”，Branch 是 “main”，目录是 “/docs”
    2. 刚开启或刚推送后要等 1~2 分钟，GitHub 需要重新构建站点

问题：点「推送」提示「连接 GitHub 失败」
    说明本机网络访问不了 api.github.com。
    浏览器打开 https://github.com 试一下，能开就是暂时性问题，
    稍后重试即可。

万能排查方法：
    双击  诊断.bat  ，它会检查：
      - Node 在哪、什么版本
      - 项目文件齐不齐
      - 端口有没有被占
      - 实测能不能启动
    把它的输出截图发出来即可定位问题。
